Desktop Vista: architecture and UX review

**All my drives. One perfect view.**  
Review date: 9 September 2026. Baseline: the local `desktop_vista.py`, labelled **v1.2-dev**, its tests, configuration, `ROADMAP.md`, original design note, and supplied icon assets.

This is a design and review deliverable. Code below is proposed integration material, not an implemented application upgrade. Existing application code, live configuration, assets and roadmap were not edited. The working tree already contained a deleted README and untracked icon assets before this review.

## 1. Recommendation and baseline correction

Finish the reliability and branding work in v1.2, then make cross-folder playlists the next substantial release. Retain CustomTkinter and the existing single-image workflow. Introduce a playback controller with explicit state before adding power rules or monitor assignments. Bring in COM behind a small wallpaper backend boundary, retaining the current global backend for explicitly global operations.

The supplied v1.0 summary is historical. Background preview loading, responsive sizing, a Fisher–Yates deck, atomic configuration replacement, tray support, startup registration and custom intervals already exist. Their presence does not establish complete resilience: several implementation gaps remain below. `ROADMAP.md` already places playlists in v1.3, power awareness in v1.4, topology/tags in v1.5 and per-monitor output in v2.0. Preserve those release names; the requested v1.1/v1.2/v2.0 matrix buckets are reconciled explicitly in section 3.

## 4. Architectural blueprint

```mermaid
flowchart LR
    UI[CustomTkinter main thread] --> PC[Playback controller]
    Tray[Tray thread] --> Q[Command queue]
    Q --> PC
    PC --> CAT[Catalogue and playlist resolver]
    CAT --> SCAN[Background source scanners]
    CAT --> DB[(Local SQLite metadata)]
    PC --> PRE[Preview worker and byte LRU]
    PRE --> OUT[Result mailbox]
    OUT --> UI
    PC --> POL[Schedule and suppression policy]
    POL --> APPLY[Serialized preparation and apply worker]
    APPLY --> SPI[Global SPI backend]
    APPLY --> COM[STA COM backend]
```

Start with a few helpers and explicit controller state in the existing file. Extract modules when a boundary is exercised by a feature, rather than splitting everything upfront. Proposed later ownership boundaries are `catalogue.py`, `playback.py`, `preview_service.py`, `windows_wallpaper.py`, and `config_store.py`.

The controller owns selected source/image, **last successfully applied image per target**, history, shuffle deck/cursor, playback intent, pause reasons and next due time. UI selection and successful desktop output are different states. Tray “Current” should report the applied image, while the main window labels its preview as selected. All apply requests carry an immutable target, image ID, source revision and generation. Recheck eligibility after slow preparation; discard superseded requests before entering the OS call. Already-running OS calls cannot be undone by cancelling a Python future.

Maintain one slideshow authority: Desktop Vista's controller. Do not run a native Windows slideshow alongside the custom scheduler. On COM failure, show the error for a selected monitor; never silently fall back to a global SPI call that changes every screen.

### Track A: multi-drive aggregation and recovery

Represent a source with a stable application ID, type (`local`, `removable`, `network`), configured root, recursion choice and optional volume identity. Retain drive-letter paths for convenience, but map removable sources through volume identity plus relative path where available. Do not equate every reappearing `F:` with the same device. UNC sources retain canonical server/share roots; Desktop Vista should not store network passwords.

A playlist references source IDs and/or image IDs. Resolve membership as a union, normalize Windows paths, then apply hidden/tag/favourite filters and deduplicate by catalogue identity. Do not hash every 4K file merely to scan a folder. Add optional content hashes lazily for exact duplicate detection; path aliases, hard links and reparse points need explicit handling. Default recursion off to preserve current behaviour, avoid traversing junctions by default, and allow users to opt into subfolders.

Store metadata locally in SQLite: `sources`, `images`, `tags`, `image_tags`, plus stable IDs and schema migrations. Images carry source ID, relative path, size, nanosecond mtime, dimensions, favourite and hidden flags. Add indexes for source and tag membership. Keep large per-image data out of `config.json`. Use a single database-writer owner and transactions; no connection sharing across arbitrary worker threads. Virtual collections are saved filter expressions over this catalogue and never duplicate or modify image files.

Use asynchronous status probes every roughly 15 seconds while relevant sources are unavailable, with longer exponential backoff for unreachable shares. Optional `WM_DEVICECHANGE` can request an immediate rescan of local volumes; it is not a replacement for UNC polling. Track `online`, `offline`, `permission_denied`, `scanning`, and `error` separately. Directory existence alone does not prove readability. Any Windows message integration must preserve the previous window procedure, pointer widths and callback lifetime; defer it until polling is reliable.

**Bounded network work:** a thread timeout does not cancel blocked filesystem I/O. Do not let two unresponsive NAS probes occupy the same pool as preview decoding. Allow at most one outstanding probe per source. For a hard timeout and predictable process exit, use a separate scanner process with structured results and a kill/restart boundary. Never terminate threads forcibly.

When a source disappears, preserve its catalogue rows and playlist membership, mark it unavailable, skip its remaining candidates within a bounded search and keep the last successful desktop. Try an available playlist source; otherwise enter “Waiting for sources” without a busy loop. An optional local last-good wallpaper cache can keep an explicitly opted-in fallback. Cache thumbnails and full-resolution fallback images separately, with configurable quotas and pruning that protects current/pending output. On reconnect, diff the source and resume only if playback was intended to run. Do not undo a user's manual pause.

### Track B: display model and COM

`IDesktopWallpaper` is available for desktop apps from Windows 8, so it fits the Windows 10/11 target. Enumerate IDs using `GetMonitorDevicePathCount` / `GetMonitorDevicePathAt`, then obtain rectangles using `GetMonitorRECT`. Enumeration can include disconnected displays; preserve their assignments and exclude invalid/empty active rectangles. [Microsoft interface documentation](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-idesktopwallpaper), [monitor enumeration details](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-idesktopwallpaper-getmonitordevicepathat).

Persist device paths, never ordinal numbers such as “Monitor 2” as identity. User-facing numbers are labels generated for the current topology and may differ from Windows Settings numbering unless explicitly reconciled. A docking or driver change can alter IDs; preserve an orphan assignment and request reassignment rather than guessing. Refresh on display changes and session resume.

`SetWallpaper(monitor_id, path)` targets a monitor; passing a null monitor ID targets all monitors. `SetPosition` has no monitor argument: **fit mode is global**. Do not expose independent per-monitor fit settings backed only by that call. Later per-monitor crop requirements need pre-rendered images sized for each display and a compatible shared fit mode. [SetWallpaper](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-idesktopwallpaper-setwallpaper), [SetPosition](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-idesktopwallpaper-setposition).

For topology cards, compute the union of active rectangles, including negative left/top coordinates. Use one uniform scale and translate by the union's minimum x/y so arrangements, portrait displays, offsets and gaps remain visible. Device resolution and physical monitor size are different; describe the strip as desktop geometry, not physical measurements. Account for Tk's logical units versus display pixels when producing previews.

Span is a global composition mode, not a separate panorama for arbitrary monitor subsets. Offer “All displays · Span” distinctly from independent assignments. Show the image over the whole desktop bounding rectangle with seams/gaps overlaid. Warn within the crop preview about lost image areas; mixed DPI, portrait displays and non-aligned tops require physical validation. Native span does not automatically add bezel correction. Windows' position enum includes centre, tile, stretch, fit, fill and span. [Position enum](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/ne-shobjidl_core-desktop_wallpaper_position).

### Track C: tray, startup, power and fullscreen

Keep Tk on the main thread. On Windows, pystray permits `Icon.run()` on a separate thread. Publish commands to a queue and refresh immutable menu snapshots from controller state. Track tray readiness and failure explicitly; never hide the only window before the notification icon is ready. Close-to-tray and minimize-to-tray are separate preferences. A normal minimize currently need not mean tray hide. [pystray lifecycle and menus](https://pystray.readthedocs.io/en/latest/usage.html).

Tray menu: current applied filename (disabled header), Next Wallpaper, Previous Wallpaper, Pause/Resume Slideshow, Reveal in Explorer, Copy Image Path, Open Desktop Vista, Exit. Disable image actions without an applied image and explain automatic pauses in a status item. Previous should traverse successful apply history; Next consumes the playlist deck. Tray actions apply immediately, subject to the chosen manual-override policy. UI arrows retain preview-only behaviour until the user presses Apply.

Startup remains opt-in under the existing HKCU Run value with `--minimized`; distinguish script execution (`pythonw.exe` plus script) from a packaged executable (executable plus flag only). Quote through `subprocess.list2cmdline` for generated Windows argument lists, not string concatenation. Compare the registry command, not just value existence, and implement single-instance ownership before login launches become routine. Treat startup registration and slideshow autostart as separate choices.

`GetSystemPowerStatus` provides AC state and a distinct Battery Saver flag (`SystemStatusFlag`). Being on battery is not itself Battery Saver. Check the API result and unknown values; use optional on-battery throttling separately from Battery Saver pause. Maintain a set of pause reasons (`user`, `battery_saver`, `fullscreen`, `no_source`) so clearing one cannot accidentally resume another. [SYSTEM_POWER_STATUS](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-system_power_status).

`SHQueryUserNotificationState` reports conditions such as busy, fullscreen Direct3D and presentation mode. It is a useful suppression signal, not a comprehensive detector of every borderless game or a measure of performance. Combine it, if necessary, with a conservative foreground-window-versus-monitor rectangle check, exclusions for the shell/app, and an explicit “Pause until resumed” control. Check HRESULTs and debounce state changes. On resume, schedule one next deadline; never replay all missed changes. [Notification-state API](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shqueryusernotificationstate).

### Track D: schedule and shuffle semantics

Fixed intervals use a monotonic clock. Wall-clock schedules use timezone-aware datetimes, an explicit timezone policy and a once-per-local-date record. Define daylight-saving behaviour: for a nonexistent local time, run at the first valid time after it; for a repeated local time, run once. After sleep or clock jumps, apply at most one currently due transition. Keep a cheap periodic scheduler tick instead of relying on enormous millisecond values in Tk.

Start time-of-day presets with four configurable local times. Solar mode is optional and uses user-provided coarse coordinates; do not silently obtain location or introduce a network dependency. Define “dawn” as a chosen twilight boundary (for example civil dawn), “day” as sunrise, “dusk” as sunset and “night” as civil dusk; use a tested solar library behind an adapter. Handle polar day/night through explicit fallback times. Recompute for date, location and timezone changes. No solar library or accuracy claim is validated in this review.

For shuffle, deduplicate and filter eligible image IDs first, then use `random.Random(seed).shuffle` once per cycle. A deck guarantees no repeated ID within that fixed cycle. Avoid repeating the last applied image at the next cycle boundary by swapping the first element with a randomly chosen later element if needed; retain all IDs. On the first cycle, remove the already displayed image if it counts as consumed. New members join the next cycle; removed/hidden/offline members are skipped without refilling repeatedly. Define “no repeat” relative to eligible membership, and disclose when the set shrinks to one item. Persist deck order, cursor and membership revision if restart continuity is required; a seed alone does not preserve cursor/history. Use a deque or index cursor, not `pop(0)`.

### Track E: preview, curation and Fluent polish

Show “Image preview” versus “Desktop crop preview” modes. Image preview preserves source aspect ratio with neutral letter/pillarboxes. Crop preview uses the selected monitor's actual ratio and global fit style, including background colour. A hard-coded 16:9 box remains a useful default, not the multi-monitor contract. Debounce resize by around 120–180 ms and decode to a quantized physical-pixel target; cap excessive target sizes. Preserve original metadata before decoder draft and EXIF rotation. A small source cannot become sharp at arbitrary size: show its actual resolution and avoid promising otherwise. [Pillow orientation and image operations](https://pillow.readthedocs.io/en/stable/reference/ImageOps.html).

Favourites and hidden status belong in local metadata. Hide offers Undo and removes the image from future playback without deleting it; an already applied image can remain until the next eligible change. Add keyboard-accessible labels and focus order to heart/hide controls. Copy Path uses Tk clipboard APIs on the main thread. Reveal uses `explorer.exe` without a command shell and reports missing files plainly.

Preview crossfade can blend two modest Pillow images briefly, capped near 15–30 fps, with cancellation on navigation and a reduced-motion setting. Desktop crossfade is a different engineering problem: `IDesktopWallpaper` exposes no documented transition-duration control. Drawing on desktop device contexts or parenting windows into undocumented shell surfaces is fragile. Recommend no custom desktop renderer in v2.0 unless an isolated prototype passes Explorer restart, RDP, multi-monitor and fullscreen tests. Avoid repeated wallpaper API calls as an animation technique.

Lock screen remains a capability spike. `Windows.System.UserProfile.LockScreen.SetImageFileAsync` accepts an `IStorageFile` and returns an asynchronous action. Verify its behaviour from the actual packaged/unpackaged Python host, policy restrictions and supported Windows builds before presenting a working command. Report failures and retain the existing lock screen; do not promise compatibility based on namespace availability alone. [Microsoft method reference](https://learn.microsoft.com/en-us/uwp/api/windows.system.userprofile.lockscreen.setimagefileasync?view=winrt-26100).

For Windows 11, try the documented DWM system backdrop attribute after obtaining the correct top-level HWND. Its modern backdrop enum requires Windows 11 build 22621; retain solid dark backgrounds on earlier systems. CustomTkinter's opaque child surfaces may obscure the backdrop, so test a limited title/header region first. Respect contrast/transparency settings. Avoid undocumented Acrylic recipes as the default Windows 10 path. [DWM backdrop support](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwm_systembackdrop_type).

## 5. Concrete Python integration blueprints

These samples demonstrate boundaries and lifecycle rules. They need integration into the application's state model and focused tests. They are not an instruction to paste several competing event loops into the current class.

### 5.1 A tray-to-Tk command bridge

**Insertion point:** helper below `build_tray_icon_image`. Construct it in `DesktopVista.__init__` after UI creation; replace `_start_tray_icon` and `_on_tray_*` dispatch with this bridge. Keep `_on_close_request`, adding a `ready` check. Call `bridge.close()` before destroying Tk. Pass an existing Pillow icon and main-thread callbacks. The `next_apply` and `previous_apply` callbacks must navigate and actually apply; eventually use controller history rather than preview indices.

```python
import queue
import threading


class TrayBridge:
    def __init__(self, root, icon_image, actions, on_ready, on_failure):
        self.root = root
        self.actions = actions
        self.on_ready = on_ready
        self.on_failure = on_failure
        self.messages = queue.SimpleQueue()
        self.closed = False
        self.ready = False
        entries = [
            ("Next Wallpaper", "next_apply"),
            ("Previous Wallpaper", "previous_apply"),
            ("Pause / Resume Slideshow", "toggle"),
            ("Reveal in Explorer", "reveal"),
            ("Copy Image Path", "copy"),
            ("Open Desktop Vista", "restore"),
            ("Exit", "exit"),
        ]
        menu = pystray.Menu(*(pystray.MenuItem(
            label, self._callback(command), default=command == "restore"
        ) for label, command in entries))
        self.icon = pystray.Icon("DesktopVista", icon_image, APP_NAME, menu)
        self.job = root.after(40, self._poll)
        self.thread = threading.Thread(target=self._run, daemon=True)
        self.thread.start()

    def _callback(self, command):
        return lambda icon, item: self.messages.put(("command", command))

    def _run(self):
        try:
            def setup(icon):
                icon.visible = True
                self.messages.put(("ready", None))
            self.icon.run(setup=setup)
        except Exception as error:
            self.messages.put(("failed", str(error)))

    def _poll(self):
        if self.closed:
            return
        for _ in range(32):
            try:
                kind, value = self.messages.get_nowait()
            except queue.Empty:
                break
            if kind == "ready":
                self.ready = True
                self.on_ready()
            elif kind == "failed":
                self.ready = False
                self.on_failure(value)
            else:
                try:
                    self.actions[value]()
                except Exception:
                    log.exception("Tray action failed: %s", value)
            if self.closed:
                return
        self.job = self.root.after(40, self._poll)

    def close(self):
        if self.closed:
            return
        self.closed = True
        self.ready = False
        self.root.after_cancel(self.job)
        # Stop after readiness to avoid a stop-before-run startup race.
        def stop_when_ready():
            while self.thread.is_alive():
                try:
                    kind, _ = self.messages.get(timeout=0.1)
                except queue.Empty:
                    if self.icon.visible:
                        self.icon.stop()
                        return
                    continue
                if kind == "ready" or self.icon.visible:
                    self.icon.stop()
                    return
        threading.Thread(target=stop_when_ready, daemon=True).start()
```

This minimal bridge uses static labels. Production integration should rebuild the menu from a locked immutable snapshot of applied filename, available actions and pause reasons, then call `update_menu`. Add a startup-ready deadline that restores the window if no acknowledgement arrives. Shutdown should record a failure if the tray thread does not exit within a bounded grace period; do not block Tk indefinitely waiting for threads.

### 5.2 COM integration with a small explicit interface

**Insertion point:** a proposed `windows_wallpaper.py` module when the COM milestone begins. Import it lazily on Windows. The interface below intentionally declares the **vtable prefix through SetPosition in native order**, including unused methods that occupy slots; do not reorder or omit the intervening methods. It is sufficient for this sample, not a full slideshow COM binding. Use one owning STA thread; initialize and release on that thread. Do not pass the COM pointer between worker threads.

```python
import ctypes
from ctypes import POINTER, c_int, c_uint, c_void_p, c_wchar_p
from ctypes.wintypes import RECT
import comtypes
from comtypes import COMMETHOD, GUID, HRESULT, IUnknown
from comtypes.client import CreateObject


class IDesktopWallpaper(IUnknown):
    _iid_ = GUID("{B92B56A9-8B55-4E14-9A89-0199BBB6F93B}")
    _methods_ = [
        COMMETHOD([], HRESULT, "SetWallpaper",
                  (["in"], c_wchar_p, "monitor"),
                  (["in"], c_wchar_p, "path")),
        COMMETHOD([], HRESULT, "GetWallpaper",
                  (["in"], c_wchar_p, "monitor"),
                  (["out"], POINTER(c_void_p), "path")),
        COMMETHOD([], HRESULT, "GetMonitorDevicePathAt",
                  (["in"], c_uint, "index"),
                  (["out"], POINTER(c_void_p), "monitor")),
        COMMETHOD([], HRESULT, "GetMonitorDevicePathCount",
                  (["out"], POINTER(c_uint), "count")),
        COMMETHOD([], HRESULT, "GetMonitorRECT",
                  (["in"], c_wchar_p, "monitor"),
                  (["out"], POINTER(RECT), "rect")),
        COMMETHOD([], HRESULT, "SetBackgroundColor",
                  (["in"], c_uint, "color")),
        COMMETHOD([], HRESULT, "GetBackgroundColor",
                  (["out"], POINTER(c_uint), "color")),
        COMMETHOD([], HRESULT, "SetPosition",
                  (["in"], c_int, "position")),
    ]


def com_wallpaper_operation(prepared_path=None, monitor_id=None, style="Fill"):
    # Run on a Windows STA owner. A persistent backend should retain one
    # instance and pump its STA messages between queued operations.
    comtypes.CoInitializeEx(comtypes.COINIT_APARTMENTTHREADED)
    wallpaper = None
    try:
        wallpaper = CreateObject(
            GUID("{C2CF3110-460E-4FC1-B9D0-8A1C0C9CC4BD}"),
            interface=IDesktopWallpaper,
            clsctx=comtypes.CLSCTX_ALL,
        )
        free = ctypes.OleDLL("ole32").CoTaskMemFree
        free.argtypes = [c_void_p]
        free.restype = None
        monitors = []
        for index in range(wallpaper.GetMonitorDevicePathCount()):
            address = wallpaper.GetMonitorDevicePathAt(index)
            try:
                device_id = ctypes.wstring_at(address)
            finally:
                free(address)
            rect = wallpaper.GetMonitorRECT(device_id)
            if rect.right > rect.left and rect.bottom > rect.top:
                monitors.append((device_id, (rect.left, rect.top,
                                             rect.right, rect.bottom)))
        if prepared_path is not None:
            if monitor_id is not None and monitor_id not in {m[0] for m in monitors}:
                raise ValueError("Selected monitor is no longer connected")
            positions = {"Centre": 0, "Stretch": 2, "Fit": 3, "Fill": 4, "Span": 5}
            if style == "Span" and monitor_id is not None:
                raise ValueError("Span requires the all-displays target")
            wallpaper.SetPosition(positions[style])  # Global fit policy.
            wallpaper.SetWallpaper(monitor_id, str(prepared_path))
        return monitors
    finally:
        # Drop the sole local COM reference before balancing this init call.
        wallpaper = None
        comtypes.CoUninitialize()
```

GetMonitorDevicePathAt returns allocated text: preserve its pointer until it is copied and free it with CoTaskMemFree. Production code must also check HRESULT/S_FALSE topology edge cases and handle topology changing during enumeration. COM calls are not an atomic multi-monitor transaction: report partial success, retain previous paths for an explicit rollback attempt, and never claim that all displays changed when only one succeeded. Validate this binding against the Windows SDK and installed comtypes version on x64 Windows before adoption; it was not invoked here.

### 5.3 Background pre-decoding with a bounded LRU

**Insertion point:** helper below `_load_preview_image`; replace `_show_current` executor submission with `service.request(token, path, pixel_box)`. Poll `service.results` from Tk and call `_on_preview_ready` only when token, path and source revision still match. Create CTkImage on Tk only. The illustrative service below keeps one active decode, one replaceable pending request, one latest result, and a byte-budgeted cache. Stat and decode happen on its worker.

```python
from collections import OrderedDict
import queue
import threading
import warnings
from pathlib import Path
from PIL import Image, ImageOps


class PreviewService:
    def __init__(self, budget_bytes=64 * 1024 * 1024):
        self.budget = budget_bytes
        self.cache = OrderedDict()
        self.bytes = 0
        self.pending = None
        self.closed = False
        self.condition = threading.Condition()
        self.results = queue.Queue(maxsize=1)
        self.thread = threading.Thread(target=self._run, daemon=True)
        self.thread.start()

    def request(self, token, path, box):
        with self.condition:
            if not self.closed:
                self.pending = (token, path, box)  # Latest request wins.
                self.condition.notify()

    def _decode(self, path, box):
        stat = Path(path).stat()
        key = (path, stat.st_mtime_ns, stat.st_size, box)
        if key in self.cache:
            self.cache.move_to_end(key)
            return self.cache[key][0]
        with warnings.catch_warnings():
            warnings.simplefilter("error", Image.DecompressionBombWarning)
            with Image.open(path) as source:
                width, height = source.size
                rotated = source.getexif().get(274, 1) in (5, 6, 7, 8)
                draft_box = (box[1], box[0]) if rotated else box
                source.draft("RGB", draft_box)
                image = ImageOps.exif_transpose(source).convert("RGB")
                image.thumbnail(box, Image.Resampling.LANCZOS)
                image = image.copy()
        if rotated:
            width, height = height, width
        value = (image, width, height, stat.st_size)
        cost = image.width * image.height * 3
        if cost <= self.budget:
            while self.cache and self.bytes + cost > self.budget:
                _, (_, old_cost) = self.cache.popitem(last=False)
                self.bytes -= old_cost
            self.cache[key] = (value, cost)
            self.bytes += cost
        return value

    def _run(self):
        while True:
            with self.condition:
                self.condition.wait_for(lambda: self.closed or self.pending is not None)
                if self.closed:
                    return
                token, path, box = self.pending
                self.pending = None
            try:
                message = (token, path, self._decode(path, box), None)
            except Exception as error:
                message = (token, path, None, str(error))
            with self.condition:
                if self.closed:
                    return
            try:
                self.results.get_nowait()
            except queue.Empty:
                pass
            self.results.put_nowait(message)

    def close(self):
        with self.condition:
            self.closed = True
            self.pending = None
            self.condition.notify()
```

Do not mutate cached Pillow images after publication. The 64 MiB limit covers cached RGB pixels, not decoder buffers, Tk copies or the whole process. Bound source pixel counts and target sizes as well. A 4K RGB image alone is about 24 MiB; decoding PNG may still require the full raster. Worker exceptions become messages, so their lifetime is independent of an `except` scope. For transparent images, add explicit background compositing shared with wallpaper preparation rather than discarding alpha blindly.

This sample is a foreground pipeline. Add at most one low-priority prefetch candidate for the next deck item when no foreground request is pending; publish prefetched pixels only into the LRU, never directly into the preview. A foreground request replaces pending prefetch. For a NAS stall requiring hard cancellation, use the process boundary discussed in Track A; the thread sample cannot cancel a blocked open. Check source stat again after decode if concurrent file replacement must be detected, and do not cache under an obsolete identity.

**Migration algorithm:**

1. Read without side effects. Missing version means v1; version 2 validates directly; newer unknown versions open in recovery/read-only mode rather than being overwritten.
2. Deep-copy and strictly validate old fields. Map each normalized unique `folders` path to a stable source ID. Retain missing drives and preserve order; recursion defaults to false. UNC paths map to network sources; detect removable media when available rather than inferring solely from drive letter.
3. Map `current_folder` to `playback_source`; if it is absent from the source list, retain the original value in `legacy_v1` and select the first source or null. Resolve `current_image` into playback state after catalogue discovery, retaining its original string for offline recovery.
4. Map old `style`, `shuffle`, known interval labels and valid `interval_custom_seconds`; old tray settings map directly with safe defaults for new keys. Do not enable startup, solar or slideshow autostart during migration. Retain a copy of the original object in `legacy_v1` to support diagnosis and export.
5. Validate the entire candidate and referential integrity before saving. Create a non-overwritten version-1 backup, then write a unique temporary sibling, flush/fsync it and use atomic replacement. Report write errors; keep the original intact. Treat database creation and JSON migration as recoverable staged operations, not an assumed cross-file transaction.
6. Migration is idempotent. The new app reads v1 and v2. **The old app is not forward-compatible**: its validator discards unfamiliar fields. Provide an explicit v1 export or restore the backup for downgrade; never run the old writer against the only v2 file.

For installed builds, migrate writable settings from the application directory into a per-user local application-data directory; keep an explicit portable mode if wanted. Do not mix that location migration with a silent reset of the user's current library.
