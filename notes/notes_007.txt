-------------------------------------------------------------------------------
DOCUMENT PURPOSE
-------------------------------------------------------------------------------

v1.7 is operational. The four-page shell, HUD, tag drawer, toasts, appearance
switch, inspection mode, 1 Hz scheduler, solar tick, history/undo, mutex, named
pipe IPC and dedicated-thread RegisterHotKey listener are in the tree. What is
not done is a short, honest list — and the v2.0 display rewrite those leftovers
collide with.

Mark's 2026-09-09 brief named five items that still require attention, plus the
six original investigation tracks. This pack does both:

  A. Close-out architecture for the five v1.7 leftovers (editors, Hidden Items,
     per-display map, Narrator verification, About/copyright).
  B. An updated viability matrix and refreshed blueprints for the six tracks,
     written against the *as-built* v1.7 process model rather than the v1.5.1
     snapshot notes_005 described.

Non-goals: implementing the features; silently resurrecting Mica/Acrylic or a
committed desktop crossfade; claiming COM per-monitor independence (still
unverified — this development machine has one display); faking Narrator output.

House rules that still bind (carried from notes_003–006, now also encoded in
module docstrings of hotkeys.py / ipc.py / windows_wallpaper_com.py):

  * Tk owns the main thread. Workers publish data; self.after is the only
    legal UI marshal. app.update() loops are not a substitute for mainloop()
    when testing background after(0, ...) callbacks (MEMORY.md, v1.7 session).
  * One wallpaper authority. Never declare IDesktopWallpaper slideshow APIs.
  * SetPosition is global. Per-monitor crop must be pre-rendered.
  * COM device paths are session-ephemeral. Do not persist them as PKs.
  * SPI remains the default until COM independence is verified on real
    multi-display hardware.
  * On COM failure, never silently fall back to SPI (would stamp every screen).
  * No NumPy, no pywin32. Frozen exe size contract (~19.5 MB) still holds.
  * Never silently geolocate. Never store network passwords.
  * Do not whole-screen-capture this machine for "visual verification"
    (MEMORY.md safety incident, v1.7 session).

0. AS-BUILT BASELINE (v1.7) — WHAT THE NEXT CHANGE MUST ACTUALLY TOUCH
-------------------------------------------------------------------------------

Process model now, not the v1.5.1 sketch:

    CustomTkinter main thread (DesktopVista)
      ├── Four pages built once: library / playback / displays / settings
      │     shown via grid() / grid_remove()  (state survives a switch)
      ├── Stage: context header / preview / HoverHUD / ToastManager / tag drawer
      ├── self.images / self.index / self._shuffle_order / self._shuffle_cursor
      │     ← STILL ONE shared deck. COM target only aims the apply.
      ├── 1 Hz heartbeat (_compute_next_due): interval | daily | solar
      ├── playback_state.json history ring (100 applied) + Undo
      ├── cfg JSON: folders, playlists, collections, tags, favourites, hidden,
      │             playback_source (folder|playlist|collection), solar, hotkeys,
      │             wallpaper_target, ui.*  — still no schema_version
      ├── ThreadPoolExecutor: preview decode (cancellable via _load_token)
      │                     + 15 s reconnect probe (off Tk thread since v1.6)
      ├── pystray daemon thread          → after(0, …)
      ├── ipc.IpcServer  (named pipe, owner-only SDDL) → after(0, …)
      ├── hotkeys.HotkeyListener (own GetMessage thread, NOT a Tk WndProc subclass)
      ├── SPI path: set_windows_wallpaper()
      └── COM path (opt-in): one STA thread, CreateObject per call, 5 s timeout
            _apply_path still WAITS on that call on the Tk thread

Facts that notes_005 listed as defects and that v1.6 actually fixed:

  * collection playback_source now survives restart.
  * solar is live, not dead config (schedule.py, NOAA-style, unit-tested
    London + Svalbard fixtures).
  * mutex + pipe + hotkeys exist and were live-verified on this machine.
  * preview decode cancels on rapid navigation; reconnect probe is off-thread.

Facts that are still true and still design inputs:

  1. Single playback pipeline. Enabling COM and picking "Display 2" plays the
     same deck; it only aims SetWallpaper at one device path.
  2. Two identity spaces. enumerate_monitors() yields GDI names (\\.\DISPLAY1)
     + RECTs. ComWallpaperBackend.enumerate_monitors() yields
     GetMonitorDevicePathAt strings (\\?\DISPLAY#…) + RECTs. The topology
     canvas and the COM picker do not share a join key. Labels are ordinal
     ("Display 1") — the identity notes_004 forbade persisting.
  3. Pause policy is session-wide, and that is correct for the APIs in use
     (GetSystemPowerStatus, SHQueryUserNotificationState). Independent
     per-monitor pause cannot be built on those two calls alone.
  4. Apply is not transactional. Span slicing will issue N SetWallpaper calls;
     a mid-loop failure cannot roll back displays that already changed.
  5. JSON catalogue will not scale to tens of thousands of images.
  6. _apply_path can block the Tk thread for up to 5 s. That is the v2.0
     ApplyQueue, not a v1.7.1-sized fix.
  7. Hidden Items was given parent-folder + offline badge + search in v1.7.
     That closed the *label* gap. It did not close the *playback-state* gap
     documented in §1.2 below. That is the significant functional gap Mark
     is right to keep on the table.

Settings page already has an "ABOUT" section. It currently renders only:

    f"{APP_NAME} {APP_VERSION}" + optional " (frozen)"

No copyright line, no rights-reserved notice, no owner, no licence pointer.
That is the About gap — a missing disclosure, not a missing page.

1. V1.7 LEFTOVERS — ANALYSIS, STRATEGY, LIMITATIONS

1.1 Playlist and collection editor dialogues
--------------------------------------------

Current state (desktop_vista.py)

  _open_playlist_editor   geometry 420x480, grab_set modal
    name entry + checkbox list of cfg["folders"] only
    Save writes through to the live playlist dict (or appends a new one)
    then optionally _load_source if that playlist is active
    validation = messagebox.showerror for empty name / no folders

  _open_collection_editor geometry 360x240, grab_set modal
    name entry + comma-separated tags_any string
    hint: "Tag images from the main window's Tags field first."
    does not reuse ui_components.TagSelector
    no live match-count preview

What notes_006 §2.5 asked for and v1.7 deferred: draft-copy-on-open, inline
field errors, two-line friendly/path display. That work is still the right
shape. It is polish-plus-correctness, not a v2.0 blocker.

The data-safety part of "draft copy" is weaker than notes_006 implied. Both
editors already mutate only inside do_save(); Cancel just destroys the
Toplevel. There is no live-binding of checkboxes back into cfg. The real
defects are interaction and completeness:

  P1  Collection editor is a raw comma string. The main window now has a
      TagSelector that preserves canonical exact-string tag semantics. Two
      editors for the same vocabulary will drift (whitespace, case, empty
      tokens) the first time someone types "Nature," in one and clicks the
      "nature" chip in the other. Reuse TagSelector. Do not invent ALL/NOT
      filters in the same change — that is a collection *semantics* change
      and belongs with the v2.1 boolean catalogue, not this dialog pass.

  P1  Playlist editor can only include folders already in cfg["folders"].
      A user whose wallpaper lives on F:\ only inside a playlist they built
      last month, then removed the folder from the library list, cannot
      re-add it from this dialog. Offer "Browse…" that calls the existing
      add-folder picker and appends to both the draft and cfg["folders"].

  P2  Fixed geometry + raw paths. folder_display_label() already exists and
      is what the checkbox text uses; the gap is the lack of a second line
      (full path + offline badge), identical to the Hidden Items row v1.7
      already ships. minsize + resizable is enough; do not build a custom
      layout engine.

  P2  messagebox validation steals focus and covers the field being
      corrected. Replace with a persistent error label under the offending
      widget. Disable Save while invalid. That is the "inline validation"
      notes_006 wanted.

  P2  No match-count on the collection editor. resolve_collection_candidate_images
      already exists. Run it against the draft tags (debounced, off-thread
      if the library is large) and show "N images match". Empty match is a
      warning, not a hard error — a user may be building the collection
      before tagging.

  P3  grab_set blocks the rest of the UI, including tray-driven navigation
      that still marshals onto Tk. Keep modal for v1.8 — a sheet/drawer is
      a larger IA change and fights the four-page model. Just make sure
      Cancel / Esc / WM_DELETE_WINDOW all take the same path (destroy,
      no write). Wire the existing Esc-closes-panel chain so a modal
      editor is treated as an "active panel".

Recommended implementation (v1.8, one sitting, no schema change)

  * Extract EditorSheet helper in ui_components.py: title, body, footer
    Save/Cancel, error_label, draft dict, on_save(draft) -> None | str error.
  * Playlist draft = {"name", "folders": list[str]}. Collection draft =
    {"name", "tags_any": list[str]} fed through TagSelector.
  * On open: copy.deepcopy the record (or empty draft). On Save: validate,
    write back, _flush_save, reload source if active. On Cancel: drop draft.
  * Tests: empty name rejected and dialog stays open; Cancel leaves cfg
    identical; collection tags round-trip as exact strings; playlist
    Browse adds a new folder to cfg["folders"]; active-playlist save
    rebuilds self.images and resets the shuffle deck (see §1.2 — the same
    reset helper).

Limitation: do not try to make the editor a live preview of the slideshow.
Reloading the source on Save is enough. A live preview would couple a
modal's draft to the single shared pipeline and surprise the user if they
Cancel after the deck already changed.

1.2 Hidden Items — the remaining functional gap
-----------------------------------------------

v1.7 closed the *disambiguation* gap (basename-only rows). The manager now
shows Path.name + parent folder + offline badge + substring search + Unhide.
That is necessary and not sufficient.

The significant functional gap is that Hide/Unhide do not maintain playback
invariants. The manager is a list editor sitting beside an engine that
still thinks in positional indices.

Evidence, _hide_current (desktop_vista.py ~2749):

  * set_membership(..., "hidden", path, True)
  * self.images = resolve_source_images(...)          # list shortens
  * self.index = min(self.index, len(self.images)-1)  # positional, not identity
  * does NOT clear self._shuffle_order / _shuffle_cursor
  * does NOT apply a replacement wallpaper if the hidden file is what is
    currently on the desktop
  * does NOT rebuild the shuffle deck

Evidence, Unhide inside _open_hidden_manager:

  * set_membership(..., False)
  * rebuilds self.images if an active source exists
  * does NOT _show_current()
  * does NOT clamp / re-find self.index by path
  * does NOT reset the shuffle deck
  * does NOT restore a source that had been emptied by hiding the last image
    back into a visible preview (the "No images left" label can remain
    stale until the next navigation)

Consequence when shuffle is on and the slideshow is running: _advance_shuffle
indexes into a deck built against the *previous* length. After one hide, a
stored index can be >= len(self.images) (IndexError) or silently land on a
different file than the deck intended. That is a correctness bug, not polish.
It is reachable from the HUD Hide button, the H shortcut, the tray equivalent
if wired, and Win+Alt+H.

Secondary gaps, in priority order:

  P1  Shuffle / index invalidation on hide and unhide. One helper,
      _rebuild_playback_after_filter_change(preferred_path=None), must:
        - resolve_source_images for the active source
        - if preferred_path is still in the list, index = that position
        - else index = min(old_index, len-1) or -1 if empty
        - always self._shuffle_order, self._shuffle_cursor = [], 0
        - _load_token += 1; _show_current() or the empty-state paint
        - _update_header_context / hidden count / favourite / tags
      Call it from _hide_current, from every Unhide, and from playlist /
      collection Save when the active source is the one just edited.

  P1  Hiding the image that is currently applied must advance the desktop,
      not only the preview. If slideshow is running OR the hidden path
      equals cfg["current_image"] (or the last history entry), call the
      existing silent apply path on the new current index. If the source
      is now empty, do not invent a wallpaper; leave the last applied
      image on the desktop and say so in the status line. Never SPI-stamp
      all monitors to "clear" a hidden image.

  P2  Orphan hidden paths. Hidden is a list of absolute paths. Rename,
      move, or delete the file and the row becomes a ghost; the new path
      is treated as a different image and will play. v1.8: "Remove missing"
      action in the manager, using Path.exists() off the Tk thread, with
      an explicit count ("Remove 4 items whose files are gone"). Do not
      auto-purge on startup — a temporarily offline NAS would wipe the
      user's curation. Same rule as the reconnect watcher.

  P2  Unhide does not offer Reveal in Explorer or a preview thumbnail.
      Thumbnails are the notes_006 drawer design; they need the same
      cancellable decode path as the stage, paged, or they will hitch a
      400-item hidden list. Ship Reveal + "Show in library" (sets index
      to that path after unhide) in v1.8; thumbnails in v1.8.1 or with
      the catalogue, not in the same change as the shuffle fix.

  P2  is_folder_online(parent) runs on the Tk thread once per visible row
      during rebuild(). For a hidden list of NAS paths that is the same
      class of freeze v1.6 moved the reconnect probe off-thread to avoid.
      Cache against self._folder_online_cache; never probe inside rebuild.

  P3  No bulk unhide / no "unhide everything in this folder". Useful,
      cheap once the rebuild helper exists. Not the reason this item is
      still open.

  P3  Hidden paths are not stable IDs. Content-hash identity is a v2.1
      catalogue concern (notes_005: path + mtime_ns + size is identity;
      hashes are lazy). Do not add dhash to the hide path in v1.8.

Limitation: Hidden is a global filter across every source kind. That is
intentional (a hidden file stays hidden in Folders, Playlists and
Collections). Do not introduce per-source hide lists in this pass — it
would fork the config key and break resolve_source_images. If a user wants
"hidden from this playlist only", that is a playlist-exclusion list, a
new field, and a different conversation.

Tests that must go in test_desktop_vista.py with this fix:

  * hide current image shrinks images, clamps index, shuffle deck is empty
  * hide then _advance_shuffle does not IndexError and does not select
    the hidden path
  * unhide of the only image in a source restores preview (index == 0)
  * unhide does not change cfg["favourites"]
  * hide of applied image records a new history entry only if a
    replacement was actually applied

1.3 Interactive per-display map — correctly blocked
---------------------------------------------------

Do not build a clickable topology in v1.8. The canvas today is a correct
read-only picture of EnumDisplayMonitors RECTs. The COM picker is a
correct read-only list of GetMonitorDevicePathAt identities. Joining them
by ordinal ("the second rectangle is Display 2") is the bug notes_004,
notes_005 §2.1.4 and notes_006 P1 all forbade.

What "blocked on display identity" actually means, operationally:

  Session join (cheap, required before any click does anything)
    Intersect each GDI MONITORINFOEX.rcMonitor with each COM monitor RECT
    in physical pixels. A unique maximum-area intersection is a join.
    Ambiguous joins (cloned displays sharing a RECT, or a zero-area
    overlap after a driver glitch) must be reported as unresolved, never
    guessed. The map may highlight an unresolved display; it may not
    assign a wallpaper to it.

  Persistent identity (required before any assignment is saved)
    Do not store GetMonitorDevicePathAt. Store a fingerprint:

        fingerprint = {
          "edid_hash": ...,          # SetupAPI / WMI if available, else null
          "adapter":   ...,          # GDI device name prefix, informational
          "width": int, "height": int,
          "origin_x": int, "origin_y": int,
          "is_primary": bool,
          "orientation": "landscape"|"portrait",
        }

    Reconciliation on WM_DISPLAYCHANGE / session resume / dock:
      1. exact edid_hash match
      2. else same size + is_primary + orientation, origin within a
         tolerance (users rearrange)
      3. else same size + orientation (the remaining unique display)
      4. else unresolved — keep the last successful wallpaper on that
         output if COM still accepts the ephemeral path this session,
         otherwise leave Windows alone and surface "Display changed —
         reassign" on the Displays page

  Until step 1 is implemented and verified on a dockable multi-monitor
  machine, a clickable map would write the wrong target with high
  confidence. That is worse than a read-only strip.

v1.8 may still improve the *read-only* strip without claiming interactivity:
label each rectangle with the joined name when the session join succeeds,
mark unresolved displays, and stop numbering COM targets as "Display N"
when the GDI name is available. That is Displays-page copy, not phase E.

Phase E (interactive map, per-display applied thumbnails, span crop
assistant, drag-to-assign) stays a v2.0 item on the fingerprinting scheme.
See §2.1.

Limitation: this development machine has one display. Session-join code
can be unit-tested with synthetic RECT fixtures (two-monitor, negative
origin, clone). Persistent reconciliation cannot be declared done without
a real dock/undock session. Same honesty gate as v1.5.1's COM backend.

1.4 Accessibility / Narrator — do not simulate
----------------------------------------------

v1.7 explicitly skipped Narrator, high-contrast and multi-DPI verification.
That was the right call. CustomTkinter is a drawing toolkit on top of Tk.
It does not automatically expose a complete UIA tree. A "Narrator mode"
that announces via toasts, or a mocked IAccessible, would certify a fiction.

What we can do in v1.8 without claiming AT support
  * Every icon-only control already has a text-equivalent route (Library
    Hidden Items button, Playback Start/Stop, footer Apply, ? overlay).
    Audit that list; add accessible names via tk widget configure(text=)
    or a tooltip that is also the name, not a hover-only string.
  * Tab order: nav rail → active sidebar page → stage header → HUD
    (focus pins it) → footer Apply → status. Hidden widgets
    (grid_remove'd pages, unmapped tag drawer, unmapped help overlay)
    must not be focus stops. This is testable without Narrator.
  * High-contrast: honour System appearance, and when
    SystemParametersInfo SPI_GETHIGHCONTRAST is on, force the "system"
    tokens plus a 3:1 minimum for text-on-fill. Do not invent a fourth
    appearance mode.
  * Multi-DPI: log tk scaling, Windows scaling per monitor, and the
    preview box at startup into --selftest. Do not "fix" mixed-DPI
    preview until we have measured it on real hardware.

What only real AT can verify (v1.8.1 gate, Mark or a designated tester)
  * Narrator scan mode can reach Apply, Start/Stop, source menu, Hide,
    Favourite, Tags, Hidden Items Unhide, editor Save/Cancel.
  * Name/role/value for CTkOptionMenu, CTkSwitch, CTkSlider-equivalents
    and the raw Tk Canvas topology are sensible, or we accept they are
    not and keep a text fallback (the Displays page already has a
    monitor list next to the canvas — that list is the AT surface).
  * Contrast in Light and Dark against Win11 default themes.
  * 125% / 150% / 200% scaling at 980×560 minimum: nothing clipped that
    is required for the exit criteria of the release under test.

Limitation: we will not reach "Narrator certified" on CustomTkinter this
year. The honest product stance is: keyboard-complete, contrast-aware,
screen-reader-best-effort, with a written test script Mark runs once on
his hardware. Publish the script in docs/VERIFICATION.md; do not add a fake
pass to ROADMAP.md.

1.5 About / copyright disclosure
--------------------------------

Mark asked for a button or description that presents an About section
showing copyright information only. The Settings page already has an
ABOUT heading and a version label. Extend that heading; do not add a
second About window unless Settings is an unacceptable home.

Required content (and only this — Settings is not a EULA surface):

    Desktop Vista  <APP_VERSION>           [frozen]
    Copyright (c) 2026–present Mark Hawksworth
    All rights reserved.
    https://github.com/hawkers63/

Optional, behind an "Licence notice" text button that opens a small
read-only Toplevel wrapping LICENSE's first paragraph + the
"PERMISSION IS NOT GRANTED…" sentence. Do not paste the full LICENSE
into the Settings sidebar (wraplength 260 px will mangle it). Do not
add credits for CustomTkinter/Pillow/pystray beyond a one-line
"Third-party notices" pointer — that is a different document.

Tray menu: add "About Desktop Vista…" that switches to the Settings page
and sees the same block. One source of copy, two entry points.

Implementation: a module-level ABOUT_LINES tuple next to APP_VERSION so
--selftest and the window share the same strings. Tests: the Settings
page contains "All rights reserved" and "Mark Hawksworth"; the string
does not include source-file paths or the user's wallpaper folders.

Limitation: this is disclosure, not a licence-change. LICENSE stays
proprietary / all-rights-reserved. About must not imply an open-source
grant.

3.1 Multi-monitor independent playback (v2.0 core)
--------------------------------------------------

Invariant to preserve until COM independence is visually confirmed on two
physical displays: wallpaper_target default remains "spi". A second
PlaybackController must be instantiable in tests without applying anything.

State per assignment (not per GDI name, not per COM path):

    Assignment
      id: str                         # stable, we mint it
      fingerprint: DisplayFingerprint # §1.3
      role: "single" | "span-member" | "span-group"
      source: {kind, id}              # folder | playlist | collection
      interval_s / schedule mode      # may share the app default
      shuffle: bool
      images: list[str]               # resolved, hidden-filtered
      index: int
      shuffle_order / shuffle_cursor
      history: HistoryStack           # last 100 applied *to this assignment*
      pause_reasons: set[str]         # union with session-wide power/fs
      last_applied_path: str | None
      last_ephemeral_monitor_id       # COM path, session only

One shared session-wide layer remains correct:

    power (Battery Saver) and fullscreen (SHQueryUserNotificationState)
    pause every controller. Per-monitor fullscreen is Future work
    (foreground HWND ∩ monitor RECT) and is not required to ship v2.0.

Controller loop (one heartbeat, N controllers — do not start N timers):

    every 1 s, already true of v1.6:
      refresh session pause reasons
      for each controller:
        if session paused or controller user-paused: skip
        if due(controller): controller.advance() -> ApplyRequest

ApplyQueue (replaces the blocking _apply_path wait):

    Tk thread                          Apply worker (existing COM STA)
      enqueue(ApplyRequest)
      paint "Applying…" on that
        assignment's card
      never wait                       SetPosition once if style changed
                                       SetWallpaper per target
                                       result = ok | partial | fail
      after(0, on_apply_done)  <------ report partial success honestly

Partial success: record which fingerprints changed, keep last-good path
on the ones that failed, toast the failure, do not roll back the ones
that succeeded (Windows will not do it for us; a rollback is just another
SetWallpaper that can also fail).

Span slicer (same release, behind the assignment role):

    Input: one source image, a span-group of assignments with origins in
    a shared virtual desktop coordinate space, optional bezel_px per gap.
    Output: N pre-rendered crops on disk under %LOCALAPPDATA%\DesktopVista\span\
    named by (source_hash, fingerprint_id, bezel, style). SetWallpaper each
    member with its crop. Fit style for a span-group is forced to Fill on
    the crop; SetPosition(Span) is only legal on the all-displays target
    and is rejected for a specific monitor today — keep that rejection.

    Mixed-DPI: crop in physical pixels (RECT from the topology join), not
    logical Tk units. A 200% laptop + 100% external is the test fixture
    that has to pass before we call span done.

    Portrait member of a landscape span: allowed, but the crop will look
    wrong; surface a warning on that assignment card rather than rotating
    the source (rotation is a different feature).

Hot-plug:

    Listen WM_DISPLAYCHANGE and power-resume. Re-enumerate both identity
    spaces, re-run session join, re-run fingerprint reconciliation, then
    either re-bind last_ephemeral_monitor_id and re-apply last_applied_path
    or mark the assignment unresolved. Do not reshuffle. Do not advance.

Pattern (illustrative):

    class PlaybackController:
        def __init__(self, assignment: Assignment, resolve, apply_queue): ...
        def set_source(self, kind: str, source_id: str) -> None: ...
        def hide_current(self) -> None:
            # MUST call the same rebuild helper as v1.8's single-pipeline
            # hide path, scoped to this controller's images/index/deck.
            ...
        def advance(self) -> ApplyRequest: ...
        def undo(self) -> ApplyRequest | None: ...

    class ApplyQueue:
        def submit(self, req: ApplyRequest) -> None: ...

hotkeys.py already runs a dedicated thread that registers bindings and

3.3 Solar calculation and time-of-day scheduler — as built
----------------------------------------------------------

schedule.py is pure, stdlib, unit-tested. The 1 Hz heartbeat already
polls a wall-clock due-time for solar/daily and a monotonic due-time for
interval, which is why sleep/hibernate does not burst. Do not replace
this.

v2.0 change: each PlaybackController gets its own next-due, but they all
ask the same schedule.py functions. Solar coordinates stay app-global
(one user, one location). Phase-tag bias stays "if the controller's
resolved list has any phase tag, prefer those; else play unfiltered and
say so in status" — already the v1.6 policy.

v2.1 weather bias is an extra predicate on the same pick function, not a
fourth schedule.mode. Empty-filter trap: if weather tags match nothing,
fall back to the solar-biased list, then to unfiltered, and disclose.
Open-Meteo, no API key, cache 15 minutes, offline = last cache then
local-only. Never block the heartbeat on the network; a worker writes
the current condition into a slot the pick function reads.

    6. Copy playback_state.json's ring into history (via = 'migrated').

    10. On failure: delete db-tmp, keep running on JSON, surface a toast.

5. HARDWARE & OPERATING SYSTEM EDGE-CASE ANALYSIS
-------------------------------------------------------------------------------

5.1 Multi-GPU

  Two adapters (laptop Intel + discrete NVIDIA, or a dock GPU) produce
  two sets of GDI device names and two sets of COM device paths. The
  session join is RECT-based and survives that. EDID is attached to the
  *monitor*, not the adapter, so a dock that routes the same panel
  through a different GPU should still match on edid_hash. When EDID is
  missing (some HDMI dongles), fall through to size+origin+primary and
  expect an unresolved assignment more often. Never key on adapter name.

5.2 Mixed-DPI scaling

  Physical RECTs from GetMonitorInfoW / GetMonitorRECT are the only
  coordinate space span cropping may use. Tk's scaling is per-process
  and follows the *primary* display on older Windows; Win10/11
  per-monitor-DPI-aware is a manifest flag the frozen exe must set
  before we promise mixed-DPI preview. v1.8 --selftest should print
  GetDpiForMonitor for every GDI monitor and tk's current scaling so
  the v2.0 work starts from a measurement, not an assumption.

  Preview box today is a logical 16:9 rectangle inside the stage. On a
  200% display the same JPEG is decoded to fewer physical pixels than
  the user thinks. That is acceptable for the stage; it is not
  acceptable for a span crop written to disk.

5.3 HDR

  IDesktopWallpaper SetWallpaper does not take an HDR flag. Windows
  Advanced Colour will tone-map a JPEG; a JXR/HDR file is outside this
  product's format list and should stay outside. Do not attempt to
  "preserve HDR" by writing a different registry key. If a user sets an
  HDR image through Explorer, our next apply of a JPEG will replace it
  — disclose that in the Displays page footnote, do not try to detect
  the Advanced Colour state every tick.

5.4 Sleep / hibernate / Fast Startup

  v1.6's 1 Hz due-time already prevents catch-up bursts. What it does
  not do is refresh topology. After resume:

    * COM object may be stale. The STA thread should drop and
      recreate the IDesktopWallpaper instance on the first failed call,
      not on every resume (avoid a resume storm).
    * Device paths may have changed. Reconciliation (§1.3) runs once
      per resume.
    * NAS folders may take tens of seconds to reappear. The existing
      15 s off-thread probe is the right mechanism; do not add a
      resume-time full rescan on the Tk thread.
    * Fast Startup (hybrid shutdown) looks like a fresh process with
      warm hardware. Treat it as a normal launch, not as a resume.

5.5 Dock / undock / clone / Win+P

  Clone mode: two physical panels share one RECT and one logical
  display. Session join will see one GDI monitor and possibly two COM
  paths with identical RECTs — that is the ambiguous-join case and
  must stay unresolved. Do not slice a span across a clone.

  Win+P "Second screen only" removes the laptop panel from the
  topology. The laptop's assignment becomes unresolved and must not
  fight to apply. When the panel returns, reconcile and re-apply
  last_applied_path.

  Device-path volatility across a dock cycle is the entire reason
  fingerprints exist. If a driver update changes EDID bytes, the user
  will reassign once; that is acceptable. Silent remapping by ordinal
  is not.

5.6 Fullscreen, UIPI, Secure Desktop

  SHQueryUserNotificationState remains the session-wide pause signal.
  It will not see a borderless windowed game; that is a known miss and
  stays Future (HWND ∩ RECT). Lock screen (Secure Desktop) is a
  different session — our hotkeys and pipe do not reach it, which is
  correct. The WinRT lock-screen setter (v2.1 research gate) writes
  the image that will appear *next* time the machine locks; it does
  not paint the current Secure Desktop.

5.7 Packaged vs unpackaged vs frozen

  The running shape is a PyInstaller frozen exe or a python[w].exe
  script. It is not an MSIX packaged app. WinRT lock-screen APIs and
  some accent APIs behave differently when unpackaged. The v2.1
  research spike must run against the frozen exe Mark actually uses,
  not against a loose `python desktop_vista.py`, and must be willing
  to return "not viable unpackaged" rather than invent a broker.
